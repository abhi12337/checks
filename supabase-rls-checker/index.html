The mistake

Every table in the public schema is reachable through Supabase's auto-generated REST API with the anon key that ships in your frontend. A table created without enable row level security, or protected by a policy with using (true) / with check (true), is open to that key.

Why it is dangerous

Without RLS, anyone can read (and, depending on grants, insert, update or delete) all rows. A (true) policy for anon means anyone on the internet; for authenticated it means any user who can sign up. Write access with (true) is how apps get their data wiped or spammed. Views in public run with the view owner's permissions by default and return every row of an RLS-protected table, and the service_role key bypasses RLS completely.

How to fix it

Enable RLS on every public table, then add policies for what each role may do:

alter table notes enable row level security;

create policy "users read own rows" on notes
  for select to authenticated using ((select auth.uid()) = user_id);

Keep using (true) only for SELECT on data that is meant to be fully public. Keep the service_role key in server-only code, never behind a NEXT_PUBLIC_ / VITE_ prefix.

FAQ

Does it connect to my Supabase project?

Not on this site. It reads your migration files and code only. The command-line tool also has an owner-only live check that is not available here.

Which files does it read?

SQL migrations (for example supabase/migrations/*.sql), .env files and frontend code that calls supabase.from('table'), so it can cross-check which tables the browser uses.

Are my files uploaded anywhere?

No. The checker is Python running inside your browser tab (Pyodide, WebAssembly). Your files are read with the browser's File API and written into an in-memory file system that exists only in this tab. The page makes no network requests except loading the Python runtime and the checker code. There are no analytics. You can disconnect from the internet after the engine has loaded and the scan still works.

Is a clean report a guarantee?

No. It is a static check for known patterns, not a penetration test. A clean report means none of these patterns were found, nothing more.

Can I run the same check on my machine or in CI?

Yes. Every checker on this site is an open-source command-line tool (MIT licence, Python 3.10+ standard library only). The results here are the same as `scan --json` on the command line, except for checks that need git (whether a file is committed or ignored), which cannot run in a browser.
