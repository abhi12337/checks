The mistake

A rules file that looks harmless but contains invisible characters: Unicode tag characters (U+E0000–U+E007F), stacked variation selectors, bidirectional controls (U+202A–U+202E, U+2066–U+2069) or zero-width characters.

Why it is dangerous

Tag characters mirror ASCII but render as nothing. Editors, GitHub diffs and code review show nothing, but the model reads the hidden text as part of its instructions. This is the "rules file backdoor": a rules file that tells the agent to add a script, a dependency or a backdoor to every file it writes. Bidi controls change the displayed order without changing what the model reads ("Trojan Source").

How to fix it

  1. Remove the hidden characters, then check what is left (print the file with every non-ASCII character escaped, or use a hex viewer).
  2. Find out how it got there (git log -p --follow -- <file>). If it came from a pull request, a template or a downloaded rules pack, treat that source as hostile and review everything else it changed, plus any code an agent wrote while the file was in place.
  3. Make rules files reviewed code: add them to CODEOWNERS and run the check in CI.

What this checker looks for

This page runs rules-file-audit, which reads .cursorrules, .cursor/rules, CLAUDE.md, AGENTS.md, .github/copilot-instructions.md, .claude/settings.json and similar. The rules most relevant to this page:

RuleWhat it finds
RFA001Hidden text in invisible Unicode (tag characters / variation selectors)
RFA002Bidirectional control characters
RFA003Zero-width or invisible formatting characters
RFA010Instructions hidden in markup the reader does not see
RFA011Text pushed off-screen by a long run of whitespace
RFA012Encoded blob that decodes to instructions or URLs

Every finding has a rule id, a severity, file:line, the offending line (secrets masked), why it matters and how to fix it. Run rules-file-audit rules for the full list.

FAQ

Are emoji and non-English text reported?

No. Legitimate uses (joiners inside emoji and in scripts such as Persian or Devanagari, direction marks in right-to-left text) are not reported.

Does it decode the hidden text?

Yes. For tag characters the finding shows the decoded hidden text so you can see what the agent was being told.

Are my files uploaded anywhere?

No. The checker is Python running inside your browser tab (Pyodide, WebAssembly). Your files are read with the browser's File API and written into an in-memory file system that exists only in this tab. The page makes no network requests except loading the Python runtime and the checker code. There are no analytics. You can disconnect from the internet after the engine has loaded and the scan still works.

Is a clean report a guarantee?

No. It is a static check for known patterns, not a penetration test. A clean report means none of these patterns were found, nothing more.

Can I run the same check on my machine or in CI?

Yes. Every checker on this site is an open-source command-line tool (MIT licence, Python 3.10+ standard library only). The results here are the same as `scan --json` on the command line, except for checks that need git (whether a file is committed or ignored), which cannot run in a browser.
