The mistake

An MCP tool that runs subprocess.run(..., shell=True) / exec with a tool argument, opens a model-supplied path without containment, builds SQL with f-strings or template literals, fetches any URL the model gives it, or evaluates tool input.

Why it is dangerous

Tool arguments are written by the model, and the model follows instructions it reads in web pages, files, issues and emails. A shell call lets a prompt injection run any command as the user running the server. An uncontained path can be pointed at ../../.ssh/id_rsa or ~/.aws/credentials. A fetch tool can be steered to cloud metadata (http://169.254.169.254/ returns instance credentials) and localhost admin ports.

How to fix it

Do not use a shell: run a fixed program with an argument list, and validate input. Resolve paths and check they stay inside an allowed root:

subprocess.run(["git", "log", "--", ref], shell=False, check=True,
               capture_output=True, timeout=30)

ROOT = Path(ALLOWED_DIR).resolve()
target = (ROOT / path).resolve()
if not target.is_relative_to(ROOT):
    raise ValueError("path outside allowed directory")

If a command must be chosen by the model, map an allowlisted name to a fixed argv. Use query placeholders for SQL, and annotate destructive tools so clients ask before running them.

FAQ

Which SDKs are understood?

MCP servers written in Python (FastMCP / the official SDK) and JavaScript / TypeScript (the official SDK's tool registrations).

Does it run my server?

No. It reads source code only; it never imports, runs or connects to anything.

Are my files uploaded anywhere?

No. The checker is Python running inside your browser tab (Pyodide, WebAssembly). Your files are read with the browser's File API and written into an in-memory file system that exists only in this tab. The page makes no network requests except loading the Python runtime and the checker code. There are no analytics. You can disconnect from the internet after the engine has loaded and the scan still works.

Is a clean report a guarantee?

No. It is a static check for known patterns, not a penetration test. A clean report means none of these patterns were found, nothing more.

Can I run the same check on my machine or in CI?

Yes. Every checker on this site is an open-source command-line tool (MIT licence, Python 3.10+ standard library only). The results here are the same as `scan --json` on the command line, except for checks that need git (whether a file is committed or ignored), which cannot run in a browser.
